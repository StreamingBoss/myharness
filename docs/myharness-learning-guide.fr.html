ÉTAPE 01 / 12 · COMPRENDRE QUI FAIT QUOI

Découvrez votre harness

Un modèle produit une réponse à partir d’une entrée. MyHarness assemble cette entrée, propose des outils, vérifie les autorisations, exécute les actions permises et renvoie les résultats. Le navigateur vous permet d’examiner chacune de ces étapes.

À essayer dans MyHarness

  1. Ouvrez MyHarness et repérez les vues Chat, Internals, et Explore.
  2. Utilisez Chat pour suivre la conversation, Internals pour examiner les échanges avec l’API et les effets des outils, et Explore pour voir les éléments qui composent une requête.
  3. Gardez ces trois vues à l’esprit tout au long du guide : la conversation, les traces observables et la construction de la requête.

Trois vues, trois questions

Chat : Qu’a dit et fait l’assistant ?

Internals : Qu’a-t-on envoyé et reçu via l’API ?

Explore : Quels éléments composaient la requête ?

Examinez les traces dans les trois vues avant de conclure sur le fonctionnement d’un comportement.

Ce que vous apprenez
Une réponse est le résultat visible d’un processus. MyHarness permet d’examiner ce processus.

Faites une pause et expliquez : quelle partie crée le texte, et quelle partie ouvre réellement un fichier ?

ÉTAPE 02 / 12 · DISTINGUER LE HARNESS DE L’INFÉRENCE

Choisissez où le modèle s’exécute

L’inférence consiste à exécuter le modèle pour produire une réponse. L’édition navigateur exécute le harness dans un Worker ; Ollama ou un fournisseur cloud réalise l’inférence séparément.

À essayer dans MyHarness

  1. Choisissez Local Ollama ou un fournisseur cloud disponible dans la barre d’outils.
  2. Pour Ollama, indiquez l’URL du serveur et choisissez un modèle installé. Pour un fournisseur cloud, saisissez votre propre clé API et choisissez un modèle disponible.
  3. Cliquez sur New Session. Envoyez une courte salutation et vérifiez qu’une réponse arrive.

Choisissez un environnement d’exécution

Édition Qu’est-ce qui s’exécute, et où ?
Navigateur Harness et interface sur votre machine ; inférence sur Ollama ou chez le fournisseur choisi. Pas de Bash.
Node Le même cœur du harness dans Node ; interface dans le navigateur ou exécution en terminal. Bash est disponible dans les environnements Linux/WSL compatibles.

L’accès direct aux dossiers nécessite un navigateur compatible, comme Chrome ou Edge, avec HTTPS ou localhost.

Ce que vous apprenez
Ollama utilise votre serveur de modèles. Un fournisseur cloud reçoit le contenu de la requête et facture l’utilisation de l’API sur le compte associé. Un abonnement à une application de chat ne configure pas un compte API.

Faites une pause et expliquez : pouvez-vous identifier où s’exécute le modèle que vous avez choisi ?

ÉTAPE 03 / 12 · REGARDER AU-DELÀ DE LA BULLE DE CHAT

Envoyez votre première requête

Chaque appel au modèle comprend une requête sortante et une réponse entrante. Internals permet de comparer ce que vous avez tapé avec ce qui a réellement été envoyé.

À essayer dans MyHarness

  1. Envoyez : Explique en trois phrases ce que fait un harness d’IA.
  2. Ouvrez Internals et retrouvez les blocs SENT et RECEIVED correspondants.
  3. Retrouvez votre message dans SENT. Repérez ensuite les instructions et les définitions des outils activés qui l’accompagnent.

Lisez le contenu comme une liste de contrôle

① Les instructions définissent le cadre de la tâche.

② Les messages conservés assurent la continuité.

③ Les définitions d’outils présentent les opérations disponibles.

④ Votre dernier message demande un travail.

Il s’agit d’un schéma conceptuel. Examinez le corps natif de SENT pour connaître le format réel de votre fournisseur.

Ce que vous apprenez
Le modèle reçoit un contenu structuré, qui comprend plus que votre dernière phrase. Les formats varient selon les fournisseurs.

Faites une pause et expliquez : quelles informations supplémentaires accompagnaient votre question ?

ÉTAPE 04 / 12 · DÉCOUVRIR POURQUOI UNE CONVERSATION SEMBLE CONTINUE

Expérimentez avec la mémoire

La mémoire du harness est le contenu de conversation conservé puis renvoyé dans les requêtes suivantes. Elle est distincte de l’apprentissage de nouveaux faits dans les paramètres du modèle.

À essayer dans MyHarness

  1. Avec Harness memory activée, dites : Mon nombre préféré est 42.
  2. Demandez : Quel est mon nombre préféré ? Comparez les deux blocs SENT et retrouvez l’échange précédent.
  3. Désactivez la mémoire et posez de nouveau la question. Dans cette interface, cette action réinitialise la mémoire conservée. Examinez la requête plus courte ; l’historique visible peut encore contenir l’ancien échange.

Expérience hors ligne : que reçoit le modèle ?

Nous avons déjà dit : « Mon nombre préféré est 42. » Activez ou désactivez la mémoire pour examiner une illustration de la requête suivante.

La présence d’une ancienne bulle de chat à l’écran ne prouve pas qu’elle a été envoyée au modèle. Examinez SENT pour voir les informations qu’il pouvait utiliser.

          Le prompt de base, le rôle de l’agent et le fichier AGENTS.md du projet peuvent être assemblés dans le message système. Ils guident le comportement sans modifier le modèle lui-même.

    2. 
              
  2.

    3. 
              
  3. 
                Posez la même question dans des sessions séparées, avec des instantanés d’instructions différents. Comparez d’abord SENT, puis les réponses.
              
    4.

  3.

          Autorisez ou refusez une modification
        

        

          Les autorisations vous permettent d’examiner une écriture, une modification ou une commande shell proposée avant son exécution. Un refus est aussi une information : le harness le renvoie comme résultat d’outil.

  3.

          ÉTAPE 08 / 12 · VOIR LES INSTRUCTIONS APPARAÎTRE À LA DEMANDE
        

        

          Chargez une compétence
        

        

          Une compétence, ou skill, présente d’abord une courte description, puis charge des instructions plus détaillées lorsqu’on l’utilise. Elle enseigne une procédure ; elle n’exécute pas le travail de façon autonome et ne crée pas un nouvel outil.
        

        

          

            

              À essayer dans MyHarness
            

            
    
              
  1. 
                Activez use_skill et examinez les descriptions des compétences proposées.
              
    2. 
              
  2. 
                Tapez /write-readme puis votre demande. Les noms de compétences reconnus apparaissent en bleu ; l’autocomplétion après la barre oblique peut vous aider à choisir.
              
    3. 
              
  3. 
                Examinez les instructions chargées et la requête suivante. Comparez leur taille et leur niveau de détail avec la courte description initiale.
              
    4. 
            

          

          

            

              Les instructions deviennent disponibles
            

            
          

        

        

          Ce que vous apprenez
Une compétence fournit des instructions. Les outils de fichiers effectuent toujours les lectures et les écritures, et les autorisations applicables continuent de régir ces actions.

          ÉTAPE 09 / 12 · COMPRENDRE LES CONNEXIONS À D’AUTRES SERVICES
        

        

          Découvrez des outils externes avec MCP
        

        

          MCP, le Model Context Protocol, permet à des serveurs externes de fournir des outils, des instructions, des ressources et des prompts. Un serveur doit être connecté avant que ses outils réels soient connus.
        

        

          

            

              À essayer dans MyHarness
            

            
    
              
  1. 
                Ouvrez Explore → MCP servers → Find MCP servers…. Recherchez dans le registre officiel et examinez une entrée.
              
    2. 
              
  2. 
                Pour un serveur distant, utilisez Preview tools pour examiner les outils, prompts et ressources annoncés sans appeler les outils. Utilisez Show configuration pour voir les conditions de connexion.
              
    3. 
              
  3. 
                Après avoir configuré un serveur de confiance, sélectionnez les outils à proposer au modèle. Examinez l’autorisation d’un appel et ses échanges JSON-RPC dans Internals ou dans la vue du serveur.
              
    4. 
            

          

          

            

              Quatre éléments qu’un serveur peut fournir
            

            

              Outils : des opérations que l’on peut appeler.
            

            

              Instructions : des consignes ajoutées quand ses outils sont sélectionnés.
            

            

              Ressources : du contenu listé ou lu par les outils de ressources.
            

            

              Prompts : des procédures invoquées avec /mcp__server__prompt.
            

            

              L’aperçu du registre sert à découvrir. Il n’exécute pas les outils annoncés et ne lance pas les paquets locaux.
            

          

        

        

          Ce que vous apprenez
Les outils MCP ne sont pas cochés dans une nouvelle session. Lorsque les autorisations sont activées, chaque appel d’outil externe demande votre accord. Les connexions MCP du navigateur nécessitent HTTP/CORS compatible ; les serveurs locaux via stdio nécessitent Node. La connexion OAuth n’est pas prise en charge actuellement.
        

        

          Faites une pause et expliquez : que peut faire ce serveur, et quels arguments votre appel lui enverrait-il ?
        

        
      

      

        

          ÉTAPE 10 / 12 · COMPRENDRE L’ESPACE DE TRAVAIL DU MODÈLE
        

        

          Explorez les tokens et le contexte
        

        

          Les tokens sont des unités propres au modèle qui servent à encoder l’entrée et la sortie. Le contexte comprend les instructions, les messages conservés, les définitions d’outils et leurs résultats. Un historique plus long peut exercer davantage de pression sur le contexte.
        

        

          

            

              À essayer dans MyHarness
            

            
    
              
  1. 
                Examinez l’indicateur de contexte et comparez un échange court avec un échange plus long contenant des résultats d’outils.
              
    2. 
              
  2. 
                Ouvrez Explore → tokenization of a saved request. Sélectionnez un appel au modèle et cliquez sur Inspect selected request.
              
    3. 
              
  3. 
                Lisez le libellé qui décrit la mesure. Lorsque les unités sont disponibles, cliquez sur l’une d’elles pour voir sa position, son identifiant et ses octets. Un simple compte ou un résultat indisponible ne révèle pas les limites entre tokens.
              
    4. 
            

          

          

            

              Expérience hors ligne : un budget de travail
            

            

              Valeurs pédagogiques inventées · pas une estimation de tokens
              

                
              

              

                Instructions 12 %MémoireRésultats d’outilsRéserve de sortie 20 %
              

              
              

              

            

            

              La taille réelle en tokens dépend du modèle et du contenu envoyé. Résumer la mémoire ne supprime pas les définitions d’outils et ne garantit pas la conservation de tous les faits importants.
            

          

        

        

          Ce que vous apprenez
Un compte de tokens n’est pas une trace complète de l’inférence. Les tokenizers configurés et la tokenisation du texte par les fournisseurs ont des limites de couverture ; les modèles de mise en forme internes du cloud sont indisponibles. Une nouvelle inspection peut consommer du quota fournisseur ou charger un modèle local.
        

        

          Faites une pause et expliquez : ce nombre est-il mesuré, estimé, limité à un compte, ou fondé sur une partie du texte seulement ?
        

        
      

      

        

          ÉTAPE 11 / 12 · DISTINGUER L’HISTORIQUE DE LA MÉMOIRE DE TRAVAIL
        

        

          Résumez, réinitialisez et sauvegardez
        

        

          La compaction demande au modèle choisi de résumer la mémoire conservée. La réinitialisation efface cette mémoire. Aucune de ces opérations n’efface l’historique sauvegardé. Un résumé entraîne une perte d’information et peut omettre des détails utiles.
        

        

          

            

              À essayer dans MyHarness
            

            
    
              
  1. 
                Créez une courte conversation avec un objectif, une contrainte et une décision. Examinez la mémoire conservée dans Explore.
              
    2. 
              
  2. 
                Utilisez la commande de compaction et examinez sa requête distincte au modèle ainsi que le résumé obtenu. Comparez les détails d’origine avec le résumé. Un résumé inefficace ou interrompu laisse la mémoire inchangée.
              
    3. 
              
  3. 
                Utilisez Export session pour sauvegarder l’historique, la mémoire actuelle du modèle et l’instantané des instructions. Le JSON de session inclut le chemin du projet ; les fichiers du projet restent dans le dossier de travail.
              
    4.

          Faites une pause et expliquez : une nouvelle réponse pourrait-elle encore retrouver un détail omis dans la mémoire conservée ?

          Menez votre propre expérience
        

        

          Vous disposez maintenant d’une méthode reproductible : prévoir un comportement, modifier un paramètre, examiner la requête et les actions réelles, puis comparer le résultat. MyHarness devient ainsi un laboratoire pour comprendre les systèmes d’IA.
        

        

          

            

              À essayer dans MyHarness

    2. 
              
  2. 
                Utilisez un petit projet et des sessions séparées pour comparer deux situations en gardant le même fournisseur, le même modèle et la même tâche. Notez les prompts, les outils activés et les instantanés d’instructions pertinents.
              
    3. 
              
  3. 
                Examinez les traces avant de conclure. Répétez si nécessaire : les générations peuvent varier. Expliquez à la fois votre observation et ses limites.
              
    4. 
            

          

          

            

              Votre carnet d’expériences
            

            

              Question : Quel comportement est-ce que j’étudie ?
            

            

              Prévision : Que dois-je voir changer ?

          Ce que vous apprenez
Le raisonnement affiché du modèle est un texte exposé par le fournisseur ; il ne garantit pas un accès au raisonnement interne. Les démonstrations du guide sont des illustrations ; vos traces sont les résultats d’outils réels et les blocs SENT.

          À garder sous la main
        

        

          Un petit glossaire
        

        

          
            Modèle, harness et inférence
          
          

            Modèle : le système qui génère une sortie à partir d’une entrée. Harness : la couche de pilotage qui organise les instructions, la mémoire, les outils et les actions autour du modèle. Inférence : l’exécution du modèle pour produire une sortie.
          

        

        

          
            Mémoire, historique et contexte
          
          

            Historique : la trace visible de la conversation. Mémoire conservée : le contenu de conversation gardé pour les appels futurs. Contexte : l’entrée disponible pour un appel donné, y compris les instructions et les outils. Ces notions sont liées, mais distinctes.
          

        

        

          
            Outil, compétence et serveur MCP
          
          

            Outil : une opération que l’on peut appeler. Compétence (skill) : des instructions pour une procédure. Serveur MCP : un fournisseur externe d’outils et d’autres éléments de contexte via un protocole commun.
          

        

        

          
            Tokens, compaction et traces
          
          

            Token : une unité d’encodage propre à un modèle. Compaction : le résumé de la mémoire pour réduire sa taille. Traces : les contenus envoyés, appels, résultats et mesures explicitement identifiées que vous pouvez examiner.
          

        

        

          Les prochaines découvertes
        

        

          Après ces expériences, explorez les modèles de mise en forme d’Ollama et la reconstruction illustrative du prompt Qwen dans Explore, comparez les contenus natifs des fournisseurs, ou utilisez le mode sans interface pour observer le même harness. Lisez la documentation d’architecture avant d’étendre le backend.
        

        

          Ce guide décrit les fonctions d’apprentissage documentées. Les sous-agents indépendants, les entrées multimédias, les outils hébergés par les fournisseurs et les réglages avancés du raisonnement ne sont pas présentés comme des exercices disponibles.
