myharnessGuide & Setup

Understand what makes an agent work.

Start with guided experiments. Then connect your own model and explore your own tasks.

The LLM proposes. The harness supplies context, controls tools, and manages the loop.

The LLM is external to the harness. A model connection supplies inference; a workspace or MCP connection supplies capabilities. This page guides your experiments in the existing harness.

1. Learn through experiments

Follow these lessons manually. Each comparison starts in a new session with the same model and task. Use a disposable browser workspace or scratch local folder.

The model and the harness

Task: Read src/greeting.py and explain what it does.

First disable Tools. Ask the task. Then start a new session, enable Files tools, and repeat it using the bundled example project.

Observe: inspect the model request, tool call, file result, and subsequent response. Which facts came from a file read? A fluent answer without a tool call does not establish that the model accessed your files.

This shows a capability difference, not that one model is more intelligent. Answers may vary. You can copy this prompt; the guide does not submit it automatically.

Tools and where they run

Task: List the project files, then tell me which tools you can use to run a script.

Compare the browser workspace with a paired native bridge, using scratch code. In browser-only mode Bash is unavailable. A bridge adds local capability grants; Ollama alone does not.

Try your existing GitHub MCP connection separately. It supplies repository tools on a remote service, not a local shell. Observe tools offered by the backend and the requests/results they produce.

Do not interpret unavailable commands as simulated successful execution. Tool access also depends on permissions and service connectivity.

Instructions and memory

Task: My example project name is Lantern. Remember it for this conversation. Follow with What project name did I give you?

Repeat in a fresh session with Memory disabled. Inspect the requests to see whether the previous messages were included. Then change an instruction and repeat a small task, holding the model and tools constant.

The harness constructs model context; this is not training the model or proving it has permanent memory. A correct guess is not evidence of stored context.

Use Explore to inspect agent instructions and skills. Load a skill and observe how its text enters the request. For context management, inspect the context controls and events when trimming or compaction occurs; estimates are not exact provider token counts.

Approvals and the agent loop

Task: Write note.txt containing hello.

Use an empty disposable workspace, enable file writes and Ask approval. Reject the first proposal. Repeat the task and approve the new proposal.

Observe the request, proposed change, approval outcome, effect, and next model response. Verify the actual file. Stop a waiting proposal to see cancellation. Missing approval answers never authorize a change.

A model saying it wrote a file is not proof of execution. The approval policy belongs to the backend; the UI displays the decision.

Then try your own task

Use browser files, a local folder, a native bridge, or the existing MCP connections. Check the current harness's Explore view for the effective capabilities and instructions.

2. Set up your experiment

Privacy on this device

Credentials, conversations, settings, and browser workspace copies stay in memory. Existing saved work is not loaded. Credential saving is disabled.

Conversations and browser workspace copies persist unencrypted. Credentials are saved only when you opt in to the vault below.

Credential vault

Use at least 12 characters. Forgotten passphrases cannot be recovered. Deleting a vault removes its saved credentials, not conversations.

Local bridge

Optional

Makes a local project the native workspace. File, Git, Bash, and web-search tools use the paired bridge. Local grants still apply. Unpair bridge removes its tools and returns to your previous browser workspace while keeping your model connection and conversation.

Start a bridge at home

Use Linux, macOS, or Windows through WSL. Choose an unused port and an exact website origin.

npm run bridge:ts -- --workspace /path/to/scratch --origin https://your-site.example --port 5002 --allow-tokenizer --allow-writes --allow-commands --allow-git-writes

To inspect Ollama token pieces, install llama.cpp once and add --allow-tokenizer when starting the bridge. It locates the selected local Ollama model, starts llama-server on an unused loopback port, reuses it, and stops it when unpaired or shut down. General Bash access is not required.

If llama-server is outside PATH, set MYHARNESS_LLAMA_SERVER=/absolute/path/to/llama-server in the bridge terminal. Use the same Ollama URL in the model connection and OLLAMA_URL on the bridge. Docker, WSL or remote Ollama may require a matching local file:

export MYHARNESS_TOKENIZER_MODELS='{"qwen3:8b":"/absolute/path/to/matching-model.gguf"}'

In the linked harness, open Explore → tokenization of a saved request → Inspect selected request. Ollama must support prompt rendering. The tokenizer loads the GGUF into a separate CPU process; pieces are separately tokenized evidence, not an inference trace. Existing MYHARNESS_TOKENIZERS service bindings remain supported.

Commands run with your account permissions. The project folder is not an OS sandbox. Do not use the owner's port 5000.

GitHub and other MCP services

Use the existing harness's MCP configuration. Browser connections require HTTP and server CORS support. GitHub model access and GitHub repository access are different connections.

Save or restore MCP credentials

Personal-device mode and an unlocked vault are required. Paste your HTTP MCP configuration. Header values are saved only by the explicit Save action; normal configuration storage strips them.

Ready to explore?

Open the current harness in its own tab. Its layout and displays stay unchanged.

Keep this guide open. Closing the harness tab or closing/reloading this guide ends the experiment and clears unlocked credentials. Reloading the harness reconnects to the same experiment. On shared computers, inactivity locks credentials after ten minutes. On private computers, connections stay open until you lock, unpair, or end the experiment.

End session clears temporary browser data; approved changes to local files, GitHub, and downloaded exports remain. On a personal device, encrypted credentials and saved work remain.

Saved credentials require the passphrase to unlock. This does not protect an already-unlocked session from another person, malicious same-origin scripts, browser extensions, or a compromised device. Copilot integration remains a research milestone.
